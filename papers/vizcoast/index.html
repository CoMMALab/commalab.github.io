Using VLM Reasoning to Constrain Task and Motion Planning

Muyang Yan1*, Miras Mengdibayev2*, Ardon Floros2, Weihang Guo3, Lydia E. Kavraki3, Zachary Kingston2
1Robotics Institute, Carnegie Mellon University, 2Department of Computer Science, Purdue University, 3Department of Computer Science, Rice University
*Equal contribution
Paper arXiv Code

VIZ-COAST uses VLMs and SMT-based task planning to constrain TAMP problems. Our constraints generalize to unseen problem instances within a broader domain.

Abstract

In task and motion planning, high-level task planning is done over an abstraction of the world to enable efficient search in long-horizon robotics problems. However, the feasibility of these task-level plans relies on the downward refinability of the abstraction into continuous motion. When a domain's refinability is poor, task-level plans that appear valid may ultimately fail during motion planning, requiring replanning and resulting in slower overall performance.

Prior works mitigate this by encoding refinement issues as constraints to prune infeasible task plans. However, these approaches only add constraints upon refinement failure, expending significant search effort on infeasible branches. We propose VIZ-COAST, a method of leveraging the common-sense spatial reasoning of large pretrained Vision-Language Models to identify issues with downward refinement a priori, bypassing the need to fix these failures during planning.

Experiments on three challenging TAMP domains show that our approach is able to extract plausible constraints from images and domain descriptions, drastically reducing planning times and, in some cases, eliminating downward refinement failures altogether, generalizing to a diverse range of instances from the broader domain.

Method

VIZ-COAST consists of three components:

  • SMT-based task planner. A task planner built on the Z3 SMT solver with a Madagascar or SATPlan encoding, which allows flexible constraint specification while introducing minimal search overhead.
  • Visual Reasoning Module (VRM). Before planning begins, the VRM uses a VLM to analyze an example scene (image and geometric state), the PDDL domain and problem, and the grasp specification. It foresees downward-refinement failures and infers general constraints to prevent them, written as a Python file of constraints on the SMT solver.
  • Stream-based grounding. Task plans are grounded to motion with the streams framework used in PDDLStream and COAST.

On a new problem, the task planner applies the constraints to block infeasible task plans. After K refinement failures, the VRM revises its constraints using the cached failure feedback.

Domains

  • Shelf. Rearrange blocks in a restrictive shelf to move the red block to the center tile. The shelf only allows grasps from one direction, so any block in the approach corridor causes a collision, which the symbolic domain does not encode.
  • Packing. Pack slabs, big blocks and small blocks into a container and close the lid. The symbolic domain ignores the container's limited volume, so items must be stacked in a configuration that fits under the lid.
  • Cooking. Two arms use a frying pot and a steaming pot to cook and serve ingredients. The symbolic domain neglects lids blocking pots, each arm's limited reach, unstable lid stacking, and lids occupying plates.
